<threat_model>
**ASVS L1 — Phase 1 auth threats (block_on: high)**

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| TM-01 | Deploy key / JWT private key reaches the browser bundle | HIGH | Only `VITE_CONVEX_URL` is allowed in `src/`; `convex/auth.ts` and `convex/http.ts` live in the server-side `convex/` tree and are never imported from `src/`; verification greps the built `dist/` bundle for `JWT_PRIVATE_KEY`, `CONVEX_DEPLOYMENT`, and `CONVEX_DEPLOY_KEY` |
| TM-02 | Brute-force / credential stuffing against the password provider | HIGH | Rely on `@convex-dev/auth`'s built-in `authRateLimits` table; do not hand-roll a limiter; add client-side minimum length (8) + rejection of obviously weak passwords, and surface provider rate-limit failures as a friendly generic message |
| TM-03 | Open redirect after login via `?next=` | HIGH | `ProtectedRoute` keeps the `^\/(?!\/).*$` allowlist from plan 01-01; only single-leading-slash relative paths are honoured, everything else falls back to `/chat` |
| TM-04 | Account enumeration through distinct sign-up vs sign-in errors | MEDIUM | `src/lib/errors.ts` gains one shared generic string for auth failures; forms never render the provider's raw error object |
| TM-05 | Authenticated flash / protected content leak before session resolution | MEDIUM | `ProtectedRoute` renders a neutral loading state while `isLoading` is true and only branches on `isAuthenticated` after resolution; no redirect until resolved |
| TM-06 | Stale session after logout keeps protected data mounted | MEDIUM | Sign-out calls `signOut()`, then `AuthProvider` resets router state to `/`; the chat placeholder is unmounted by the route change |
</threat_model>
