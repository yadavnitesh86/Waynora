**As a** traveler, **I want** to type a trip request, see it immediately, wait honestly, and receive the real generated plan as readable Markdown — with my prompt and history preserved through any failure — **so that** I can plan my trip without losing my words or being misled.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input -> cookie storage | Composed trip requests flow into persisted conversations |
| Backend answer -> Markdown renderer | Untrusted assistant content crosses into the DOM |
| Controller status -> React state | Request lifecycle transitions cross into the UI |
| Cookie snapshot -> application state | Persisted conversations cross back into memory on load |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | Tampering | assistant Markdown | mitigate | Answers render through the UNCHANGED Markdown.tsx (no rehype-raw, urlTransform blocks non-http(s)/mailto schemes, allowedElements whitelist); hostile-fixture tests assert no script element and no javascript: href in the DOM (CHAT-06, QUAL-03) — BLOCKING task: the hostile-Markdown test in Chat.test.tsx must pass before this plan is done |
| T-03-08 | Tampering | cookie data | mitigate | All reads go through the Phase 2 repository (Zod strictObject validation, salvage-or-reject recovery); the route never hand-parses cookies (PERSIST-04) |
| T-03-09 | Denial of Service | cookie overflow | mitigate | writeConversations enforces the retention caps and returns evicted ids; eviction of the active conversation shows the StorageNotice and never blocks the request (D-20, PERSIST-05) |
| T-03-10 | Spoofing | duplicate submission | mitigate | The composer disables submit while busy and the controller enforces single-flight, so one click can never start two expensive server runs (CHAT-08) |
