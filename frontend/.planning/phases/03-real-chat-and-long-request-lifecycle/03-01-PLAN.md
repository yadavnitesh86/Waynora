## Phase Goal

**As a** traveler, **I want** my request to reach the real backend and resolve honestly — success, failure, timeout, or stop — **so that** I never see a fabricated answer, a lost request, or a result that belongs to another session.

<objective>
Build the headless request lifecycle core: the failure taxonomy with verbatim customer-safe recovery copy, the request controller state machine (timeout/abort lifecycle, request IDs, single-flight, stale-result rule), and its React adapter hook.

Purpose: The controller is the engine that makes every later surface honest. It enforces one active request per conversation, supports waits up to the 20-minute budget, distinguishes timeout from user-stopped aborts, and silently drops stale results after unmount or conversation change (WAIT-01/02/06).
Output: Pure controller + failure taxonomy module + React hook adapter, fully tested in node and jsdom environments.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser fetch -> askBackend | Untrusted network response crosses into application state |
| Controller -> React state | Request lifecycle status crosses into the UI |
| User input -> /ask payload | Composed question text crosses to the backend |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | ask response | mitigate | askBackend validates every response through askResponseSchema (Zod strictObject) before the controller can emit succeeded — a malformed or unexpected body becomes failure "malformed", never a render (CHAT-04/CHAT-09) |
| T-03-02 | Denial of Service | timeout/abort lifecycle | mitigate | Single AbortController per request; one setTimeout cleared in a finally on every exit path; dispose() on unmount aborts and drops late results — no dangling timers or listeners (WAIT-02/WAIT-06) |
| T-03-03 | Tampering | stale results | mitigate | Every result carries the requestId captured at submit; results arriving after dispose() or for a superseded request are dropped silently, never rendered (WAIT-06) |
| T-03-04 | Repudiation | duplicate submission | mitigate | Single-flight rule: submit() while a request is active is a no-op, so one expensive server run can never be doubled from the UI (CHAT-08, PROJECT single-flight rule) |
| T-03-05 | Information Disclosure | error copy | mitigate | All failure copy comes from RECOVERY_COPY (customer-safe, verbatim); raw AskResult.message, error.message, status codes, and stack traces never reach the UI (QUAL-01) |
| T-03-06 | Tampering | abort reason | mitigate | abortSource is set before abort() fires ("timeout" from the budget timer, "user" from stop()), so timeout and user-stopped aborts map to distinct honest copy (WAIT-05) |
</threat_model>
